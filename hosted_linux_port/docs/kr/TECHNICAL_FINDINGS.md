# 기술 분석 보고서: Innioasis Y1 (MT6572) 호스티드 리눅스 포트

## 2. 오디오 서브시스템 (`/dev/eac`)

### 2.1 인터페이스 및 데이터 흐름
MT6572의 ALSA 서브시스템은 다운스트림 MediaTek 커널에서 대부분 우회되며, 향상된 오디오 컨트롤러 문자 디바이스(`/dev/eac`)가 직접 사용됩니다.
- 포맷: 16비트 부호 있는 인터리브 스테레오 PCM (리틀 엔디언), 프레임당 4바이트.
- 지원 하드웨어 샘플 레이트: 44,100 Hz 및 48,000 Hz.
- 입출력: `/dev/eac`에 대한 블로킹 `write()` 호출. 링 버퍼 용량은 8,192바이트(2,048 스테레오 프레임, 44.1 kHz에서 약 46.4ms 버퍼 지연)로 설정.
- 오디오 스레드 우선순위: 실시간 우선순위 80의 `SCHED_FIFO`.

### 2.2 오디오 팝 및 클릭 노이즈 제거
테스트 과정에서 트랙 전환, 샘플 레이트 변경 및 볼륨 조절 시 뚜렷한 음향 팝 노이즈가 발생함을 확인했습니다.

#### 근본 원인
1. **클록 분주기 불연속성:** MT6323 DAC 복원 필터가 동작 중인 상태에서 44.1 kHz와 48.0 kHz 간 PLL 분주기를 전환하면 급격한 DC 과도 전압 스파이크가 발생함.
2. **버퍼 플러시 절단:** DMA 버퍼를 비우지 않고 오디오 재생을 중단하여 앰프 전원이 차단되기 전 출력단에 잔류 전압 오프셋이 남음.
3. **FM 라디오 신호선 공유:** 아날로그 라디오 신호 경로가 앰프 바이어스 라인을 공유하여 디지털 오디오 상태 변경 중 라인 간섭이 유입됨.

#### 해결 조치
- **안정화 램프(Settling Ramp):** 오디오 정지 또는 트랙 전환 시, 디바이스를 닫거나 샘플 레이트 IOCTL을 호출하기 전에 진폭 0의 디지털 무음($0x0000$) 256샘플을 `/dev/eac`에 미리 공급.
- **하드웨어 음소거 시퀀싱:** PLL 재구성 전에 아날로그 헤드폰 앰프 라인을 음소거하고, 유효한 오디오 프레임이 DMA에 큐잉된 후에만 음소거를 해제.
- **게인 스테이징:** 소프트 블록 레벨 디더링 보간을 적용하여 디지털 감쇠로 -74 dBFS까지 볼륨을 조절. MT6323 아날로그 게인은 0 dB에서 +12 dB 헤드룸 내에서 유지하여 디지털 클리핑을 원천 방지.

## 3. 전원 관리 및 대기 전류

### 3.1 문제: 극심한 유휴 상태 배터리 소모
기기를 유휴 상태(화면 꺼짐, 음악 정지, 진단 로깅 비활성화)로 9시간 방치 시 배터리가 100% 소진되는 현상 발생.

### 3.2 근본 원인 분석
1. **CPU 동작 속도 고정:** 기본 거버너가 디스플레이 절전 시 저클록 P-State로 진입하지 않아 CPU 0이 1196 MHz에 고정되거나 불규칙하게 동작함.
2. **보조 코어 누설 전류:** Cortex-A7 코어 1이 CPU 핫플러그로 완전 차단되지 않고 WFI(Wait-For-Interrupt) 모드에 잔류함.
3. **SPM 딥 슬립 진입 불가:** 활성 드라이버들이 유지하는 웨이크록 및 주변장치 클록 인에이블 신호로 인해 MediaTek 시스템 전원 관리자(SPM)가 유휴 절전 상태에 진입하지 못함.
4. **오디오 단 정지 전류:** 오디오 출력이 멈춘 상태에서도 MT6323 차지 펌프와 헤드폰 앰프 바이어스가 계속 켜져 있음.
5. **스토리지 라이트백 주기:** 리눅스 가상 메모리의 기본 5초 더티 라이트백 주기로 인해 eMMC/SD 버스가 주기적으로 기상함.

### 3.3 해결 조치
- **화면 꺼짐 시 주파수 스케일링:**
  - 백라이트가 꺼지면 `/sys/devices/system/cpu/cpu0/cpufreq/scaling_setspeed`를 통해 CPU 0을 598 MHz로 낮춤.
  - `echo 0 > /sys/devices/system/cpu/cpu1/online` 명령으로 CPU 1을 오프라인으로 전환하여 보조 코어 전원을 완전히 차단.
- **오디오 정지 시 제로 정지 전류 구현:**
  - 오디오 정지 시 `/dev/eac`를 닫아 아날로그 헤드폰 앰프 및 DAC 바이어스 라인의 전원을 내림.
- **가상 메모리 플러시 튜닝:**
  - `/proc/sys/vm/dirty_writeback_centisecs` 주기를 12000(120초)으로 연장.
  - MMC 호스트 컨트롤러 전반에 런타임 PM(Runtime PM) 활성화.
- **SPM 딥 아이들(Deep Idle) 및 즉각적인 기상 반응성:**
  - 커널 Suspend-to-RAM(`mem`) 대신 MT6572 SPM Deep Idle(`/sys/power/dpidle_state` = 1, `cpupdn 1`)을 사용. Suspend-to-RAM 모드는 정전식 터치 컨트롤러를 중단시키고 입력 인터럽트를 비활성화하여 대기 상태에서 센터 버튼으로 기기를 깨울 수 없는 문제가 있었음. SPM Deep Idle은 터치 센서 스캔을 유지하여 센터 버튼 즉시 기상을 지원하면서도 동일한 < 5 mA 초저전력 대기 전류를 달성함.
- **최종 결과:**
  - 대기 전류가 기존 약 120 mA에서 5 mA 미만으로 대폭 감소.
  - 활성 오디오 재생 배터리 지속 시간이 약 50시간에 도달.

## 4. 부팅 시간 최적화

### 4.1 구간별 소요 시간 비교

| 단계 | 최적화 전 | 최적화 후 | 단축 시간 |
| :--- | :--- | :--- | :--- |
| 리눅스 커널 초기화 | 2200 ms | 2200 ms | 0 ms |
| initramfs: CPU 거버너 / 초기 설정 | 350 ms | 50 ms | -300 ms |
| initramfs: MicroSD 카드 감지 | 1100 ms | 280 ms | -820 ms |
| initramfs: 프레임버퍼 스플래시 및 링크 구성 | 420 ms | 80 ms | -340 ms |
| Rockbox 바이너리 재배치 | 850 ms | 420 ms | -430 ms |
| Rockbox 코어 및 UI 초기화 | 1450 ms | 850 ms | -600 ms |
| **전체 콜드 부팅 시간** | **6370 ms** | **3880 ms** | **-2490 ms (약 40% 단축)** |

### 4.2 최적화 구현 사항
1. **초기 부팅 CPU 부스트:**
   - `initramfs/init.c`의 `boost_cpu_for_boot()`를 통해 파일시스템 마운트 전에 두 Cortex-A7 코어를 1.2 GHz 성능 거버너 모드로 기동.
   - UI 설정 완료 후 Rockbox가 `y1_boot_boost_finish()`를 호출할 때까지 부스트를 유지하여 사용자 지정 CPU 프로필로 원활하게 전환.
2. **반응형 MicroSD 폴링:**
   - 100ms 정적 대기 방식을 `/proc/partitions`에 대한 10ms 주기 반응형 폴링 방식으로 교체.
   - 드라이버 등록 후 10~30ms 이내에 카드 인식이 완료됨.
3. **프레임버퍼 및 심볼릭 링크 중복 제거:**
   - 화면 상태 추적(`current_displayed_screen`)을 통해 불필요한 RAW 화면 덮어쓰기 제거.
   - `link_sdcard_to_root()`에서 `readlink()`를 검사하여 이미 존재하는 링크 생성 단계 생략.
4. **부팅 스플래시 화면 연속성 유지:**
   - `apps/main.c`의 `show_logo_boot()`가 `y1_display_raw_screen("boot")`를 호출하여 UI가 준비되기 전에 기본 Rockbox 로고가 부팅 스플래시를 덮어쓰지 않도록 개선.

## 5. 입력 시스템 및 동작 매핑

### 5.1 이벤트 노드 및 버튼 매핑 코드
리눅스 입력 이벤트가 다음과 같이 매핑됩니다:
- 센터 버튼: `KEY_ENTER` / `BTN_SELECT`
- 상단 (메뉴): `KEY_BACK` / `KEY_ESC`
- 하단 (재생/일시정지): `KEY_PLAYPAUSE`
- 좌측 (이전 곡): `KEY_PREVIOUSSONG` / `KEY_REWIND`
- 우측 (다음 곡): `KEY_NEXTSONG` / `KEY_FASTFORWARD`
- 측면 버튼: `KEY_VOLUMEUP`, `KEY_VOLUMEDOWN`
- 헤드폰 리모컨: `accdet` 드라이버 기반 `KEY_MEDIA` / `BTN_0`

### 5.2 이전 곡 / 되감기 일관성 버그 수정
- **문제점:** 고급 키 잠금 모드 및 MFB 리모컨 입력 시, 재생 진행 상태와 무관하게 이전 버튼을 누르면 즉시 이전 트랙으로 건너뛰는 현상이 발생함. 표준 Rockbox WPS 동작은 재생 시간이 3초 이상($\ge 3\text{초}$)인 경우 트랙/큐 시작 위치로 되감고, 3초 미만($< 3\text{초}$)일 때만 이전 곡으로 이동해야 함. 또한 키 잠금 상태에서 탐색(Seek) 시 조기 트랙 건너뛰기 이벤트가 방출됨.
- **수정 내용:** `apps/misc.c`에서 `BUTTON_MULTIMEDIA_PREV` 처리 시 `id3->elapsed >= DEFAULT_SKIP_THRESH`(3000ms) 여부를 검사하도록 수정. `apps/action.c`에서는 키 잠금 상태의 버튼 누름 이벤트가 탐색 중 초기 다운 상태를 흡수하고 네이티브 `ACTION_WPS_SEEK*` 액션을 발행하도록 하여 WPS 상태 화면이 정확히 표시되도록 수정.

## 6. USB 가젯 및 충전 전용 모드 전환

- 대용량 저장소: `/sys/class/android_usb/android0/f_mass_storage/`를 통해 `/dev/block/mmcblk1`(또는 `mmcblk1p1`)을 노출하는 리눅스 USB 가젯 서브시스템에 의해 관리됨.
- 충전 전용 모드: `apps/gui/usb_screen.c`에서 센터 버튼을 1초간 누르고 있으면(`BUTTON_SELECT`, 반복 시간 $\ge 1000\text{ ms}$) USB 대용량 저장소 가젯을 종료하고 SD 카드를 Rockbox 전용 읽기/쓰기 모드로 다시 마운트하여 충전 중 음악 감상이 가능하도록 구현.
- 호스트 PC 마운트 해제 및 재연결 버그 수정:
  - **문제점:** 호스트 PC에서 기기를 안전하게 제거(LoEj 비트가 설정된 SCSI `START_STOP` 명령)할 때 다운스트림 리눅스 커널의 `f_mass_storage` 드라이버가 백업 파일을 닫으면서(`fsg_lun_close`) `lun0/file`을 빈 문자열로 지워버림. 이후 케이블을 다시 연결해도 `lun0/file`이 비어 있어 윈도우에서 빈 카드 리더기("USB 드라이브에 디스크를 넣으십시오")로 인식되는 문제 발생.
  - **수정 내용:** `firmware/target/hosted/innioasis/y1/usb-y1.c`에서 USB 슬레이브 모드 진입(`usb_enable(true)` / `disk_unmount_all()`) 시마다 `y1_usb_attach_storage()`가 `/dev/block/mmcblk1`을 동적으로 검사하여 `lun0/file`에 다시 바인딩하도록 수정. `apps/gui/usb_screen.c`에서는 `y1_usb_check_host_ejected()`가 `lun0/file`을 감시하여 호스트 PC가 볼륨을 안전 제거하면 기기가 즉시 충전 전용 모드로 전환되고 가젯 바인딩을 해제하여 Rockbox 재생 화면으로 복귀하도록 구현.

## 8. 샘플 레이트 전환 및 위상 정렬 왜곡 버그

### 8.1 증상
서로 다른 샘플 레이트를 가진 음원(예: 44.1 kHz $\leftrightarrow$ 48.0 kHz) 간에 빠른 전환을 반복할 경우 음질이 눈에 띄게 왜곡되는 현상이 나타남. 전체적인 재생 볼륨(RMS)은 유지되나 사운드가 점점 탁해지고, 보컬의 중앙 음상이 실종되며, 음장감이 저 멀리 뒤로 물러나 안개 속으로 들어간 듯한 소리가 발생함.

### 8.2 근본 원인
1. **부분 쓰기(Partial Write) 시 스테레오 프레임 정렬 파괴:**
   `pcm_worker` 쓰기 루프가 기존에 불완전 바이트 카운트를 `written &= ~3`으로 버림 처리했음. 이로 인해 커널 원형 버퍼는 정렬되지 않은 바이트 수만큼 진행되었으나 사용자 공간 버퍼 카운터는 버림 처리된 수치만큼 진행됨. 다음 쓰기 시 2바이트 어긋난 홀수 바운더리에서 쓰기가 시작되어 좌/우 스테레오 채널이 뒤바뀌고 한쪽 채널이 1샘플($d \approx 22.7\,\mu\text{s}$) 지연됨. 채널 간 위상 차이로 인해 심각한 센터 채널 상쇄 및 빗살 필터링이 유발됨.
2. **PMIC FIR 보간기 내부 상태 손상:**
   PMIC 다운링크(`0x4014`) 및 마스터(`0x4000`)가 활성화된 상태에서 PMIC NewIF(`0x4024`) 및 PMIC 코덱 DL(`0x4002`)에 새 클록 분주비를 덮어씀으로써 MT6323 내부 FIR 디지털 필터 상태 머신이 손상됨.
3. **PMIC CDC 동기화 트리거 고착:**
   `top_ctl_trigger()`에서 `toggle = ((~val) << 8) & 0x300` 표현식이 `0x4016`의 비트 0과 1이 0으로 읽히는 하드웨어 특성상 비트 8과 9를 토글하지 못해 부팅 이후 CDC 클록 재동기화가 영구 불능 상태가 됨.
4. **커널 링 버퍼 잔류 프레임 누출:**
   32 KB 코히런트 DL1 버퍼를 리셋하지 않고 클록 주파수를 변경하여 이전 곡의 잔류 오디오 프레임이 어긋난 오프셋 상태에서 새로운 속도로 출력됨.

### 8.3 세부 해결 내용
- **프레임 정렬 보장:** `written & 3 != 0`인 경우 제로 패딩(`4 - unaligned` 바이트)을 `/dev/eac`에 직접 기록하여 링 버퍼의 정렬을 강제 복원. 사용자 버퍼 포인터는 `written + pad_len`만큼 전진시켜 이후 모든 프레임이 4바이트 정렬을 유지하도록 조치.
- **PMIC 게이팅 및 FIR 리셋:** `sink_set_freq()` 호출 시 레이트 레지스터를 변경하기 전에 `0x4014`와 `0x4000`을 비활성화하고, PMIC 디지털 게인(`0x4006`, `0x4008`)을 리셋한 후 마스터 제어를 깔끔하게 재가동함.
- **DL1 링 버퍼 재할당:** 샘플 레이트 변경 시 `AUDDRV_FREE_DL1_BUF`, `AUDDRV_ALLOCATE_DL1_BUF`, `SET_MEMIF_FP`를 호출하여 커널 읽기/쓰기 포인터를 0으로 초기화.
- **CDC 트리거 XOR 토글:** `pcm-eac.c` 및 `unmute_eac.c`의 `top_ctl_trigger()`에서 `(val ^ 0x300) & 0x300` 연산 방식을 적용.
- **동시성 잠금 보호:** `sink_set_freq()`를 `sink_lock()` / `sink_unlock()`으로 잠그고 `pcm_mtx` 보호 하에 `pcm_data`를 안전하게 비우도록 처리.
