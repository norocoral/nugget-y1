# 오디오 서브시스템: MediaTek EAC & MT6323

이 문서는 Innioasis Y1 호스티드 록박스(Hosted Rockbox) 포트의 오디오 하드웨어 아키텍처, 드라이버 인터페이스, 샘플 레이트 전환, 과도 팝 노이즈 억제 및 게인 스테이징(Gain Staging)에 대해 상세히 다룹니다.

## 2. 커널 인터페이스: `/dev/eac`

다운스트림 미디어텍 커널 3.4.67은 표준 ALSA PCM 디바이스 대신 향상된 오디오 컨트롤러(Enhanced Audio Controller) 문자 디바이스(`/dev/eac`)를 통해 디지털 PCM 오디오를 라우팅합니다.

### 2.1 구성 파라미터
- 샘플 레이트: 44,100 Hz 및 48,000 Hz 네이티브 하드웨어 클록킹 지원.
- 인코딩: 16비트 부호 있는 정수(`int16_t`), 리틀 엔디언, 스테레오 인터리브(L, R, L, R...).
- 프레임 크기: 스테레오 샘플 쌍당 4바이트.
- 버퍼 깊이: 8,192바이트 (2,048 스테레오 프레임, 44.1 kHz 기준 버퍼 지연 시간 약 46.4ms).
- 스레드 스케줄링: 실시간 우선순위 80의 `SCHED_FIFO`.

## 3. 과도 팝 및 클릭 노이즈 제거

### 3.1 노이즈 발생 메커니즘
1. **PLL 분주기 전환:** 44.1 kHz와 48.0 kHz 간 오디오 클록 전환 시 MT6323 델타-시그마 변조기가 급작스럽게 교란되어 DC 오프셋 전압 단차가 발생.
2. **버퍼 플러시 절단:** FIFO를 비우지 않고 오디오 출력을 중단하면 출력이 0V가 아닌 상태로 편향되어 앰프 전원이 꺼질 때 과도 클릭 노이즈가 발생.
3. **FM 라디오 신호 경로 공유:** 공유 아날로그 라인으로 인해 디지털 오디오 초기화 중 라인 간섭 발생.

### 3.2 구현된 해결책
- **디지털 안정화 버퍼:** 오디오 디바이스를 닫거나 샘플 레이트 분주기를 변경하기 전에 진폭 0의 PCM($0x0000$) 256샘플을 `/dev/eac`에 기록하여 아날로그 복원 필터가 중립 접지(Neutral Ground)로 안착할 수 있도록 유도.
- **하드웨어 음소거 시퀀싱:** PLL 클록 변경 전에 아날로그 헤드폰 앰프 라인을 음소거하고, 유효한 프레임이 DMA 링 버퍼에 미리 채워진 후에만 음소거를 해제.
- **동일 샘플레이트 바이패스:** 동일한 샘플 레이트를 사용하는 트랙 간 전환 시 드라이버 재구성을 완전히 건너뛰어 끊김 없는 갭리스(Gapless) 재생을 구현.

---

## 4. 게인 스테이징 및 볼륨 제어

게인 제어는 디지털 감쇠와 아날로그 증폭을 결합하여 처리됩니다:
- **디지털 범위 (-74 dB ~ 0 dB):** 록박스의 소프트웨어 볼륨 디더링 엔진에서 처리. 클리핑을 방지하기 위해 디지털 증폭은 절대 0 dBFS를 초과하지 않음.
- **아날로그 헤드룸 (0 dB ~ +12 dB):** MT6323 내장 아날로그 헤드폰 앰프 단계를 통해 처리되어 디지털 왜곡 없이 고임피던스 헤드폰에 충분한 구동력을 제공.

---

## 5. 헤드폰 감지 및 분리 동작

3.5mm 단자는 `accdet` 드라이버와 연결된 아날로그 임피던스 감지 스위치를 사용합니다.
- 단자 분리: `/sys/class/switch/h2w/state`를 통해 모니터링. 분리 시 록박스가 즉시 `pause_action()`을 호출.
- 재연결: `설정 -> 재생 설정 -> 헤드폰 분리 시 일시정지` 옵션이 켜져 있을 경우 다시 연결 시 자동으로 재생이 재개됨.

---

## 6. 샘플 레이트 전환 및 채널 간 위상 동기화

### 6.1 주파수 전환 시 음질 저하 문제
서로 다른 샘플 레이트(예: 44.1 kHz $\leftrightarrow$ 48.0 kHz)의 트랙을 반복해서 전환할 경우 점진적인 음질 저하가 발생했습니다. RMS 음량 수치는 동일함에도 보컬의 중앙 음상이 사라지고, 고주파 대역에 빗살 필터링(Comb Filtering)이 걸리며, 스테레오 이미지가 산만한 배경 잔향으로 붕괴("소리가 점점 먹먹해지며 멀어지는 현상")했습니다.

### 6.2 근본 원인 분석
1. **채널 간 프레임 정렬 불일치 (`pcm_worker`):**
   `write(eac_fd)`가 4의 배수가 아닌 부분 바이트 수를 반환했을 때, `written &= ~3` 코드가 사용자 공간 카운터에서는 정렬되지 않은 바이트를 잘라냈지만 커널 원형 버퍼는 정렬되지 않은 바이트 수만큼 진행되었습니다. 다음 쓰기 반복 주기에서 사용자 공간 버퍼 오프셋이 2바이트 어긋난 경계에서 시작되어 좌우 채널이 반전되고 1샘플 상당의 채널 간 시간 지연($d = 1 / f_s \approx 22.7\,\mu\text{s}$)이 발생했습니다. 샘플 레이트가 전환될 때마다 이 위상 편차가 누적되어 극심한 빗살 필터링과 파괴적인 센터 채널 상쇄가 발생했습니다.
2. **PMIC FIR 복원 필터 손상:**
   PMIC 다운링크(`0x4014`) 및 PMIC 오디오 디지털 마스터(`0x4000`)가 활성화된 상태에서 `AFE_PMIC_NEWIF_CFG0`(0x108), `AFE_I2S_CON1`(0x34), PMIC NewIF 주파수(`0x4024`), PMIC 코덱 레이트(`0x4002`)를 재구성하여 MT6323 내부의 FIR 데시메이션 및 보간 필터 지연 라인이 엉키고 복원 필터 상태가 손상되었습니다.
3. **PMIC CDC 클록 동기화 트리거 고착:**
   `top_ctl_trigger()` 함수가 레지스터 `0x4016`을 읽어 `toggle = ((~val) << 8) & 0x300`을 계산했습니다. 그러나 `0x4016`의 비트 0과 1이 항상 0으로 읽히기 때문에 8비트 시프트 연산 시 항상 고정값 `0x300`이 출력되어 후속 전환 시 필수적인 클록 동기화 엣지가 발생하지 않았습니다.
4. **커널 링 버퍼 잔류 데이터 및 포인터 불일치:**
   32 KB 코히런트 DL1 DMA 버퍼를 리셋하지 않고 클록 레이트를 변경하여 이전 곡의 잔류 샘플이 새 클록 속도로 재생되고 커널 읽기/쓰기 포인터가 임의의 0이 아닌 오프셋에서 시작되었습니다. 동시에 `sink_set_freq()`가 `sink_lock()`을 획득하지 않고 실행되어 하드웨어 레지스터 설정 도중 `pcm_worker`가 오디오 데이터를 기록하는 경합 상태가 발생했습니다.

### 6.3 구현된 해결책
- **제로 패딩 프레임 정렬:** `pcm_worker`에서 `written & 3 != 0`일 때, 제로 패딩(`4 - unaligned` 바이트)을 `/dev/eac`에 직접 기록하여 커널 링 버퍼를 4바이트 경계로 복원합니다. 사용자 공간 포인터는 전체 프레임 크기(`written + pad_len`)만큼 전진하여 4바이트 스테레오 정렬을 유지하고 채널 반전 및 위상 지연을 원천 차단합니다.
- **PMIC 게이팅:** `sink_set_freq()`에서 샘플 레이트 분주기를 변경하기 전에 PMIC 다운링크(`0x4014`)와 마스터(`0x4000`)를 0으로 게이팅하고, 레지스터 및 디지털 게인(`0x4006`, `0x4008` = 0 dB) 설정이 안정화된 후 다시 활성화합니다.
- **링 버퍼 포인터 초기화:** 샘플 레이트 전환 시 `AUDDRV_FREE_DL1_BUF`, `AUDDRV_ALLOCATE_DL1_BUF`, `SET_MEMIF_FP`를 호출하여 커널 원형 버퍼 포인터를 0으로 초기화합니다.
- **CDC 클록 트리거 토글:** `pcm-eac.c` 및 `unmute_eac.c`에서 `top_ctl_trigger()`가 `(val ^ 0x300) & 0x300`을 사용하여 클록 동기화 비트를 토글하도록 수정했습니다.
- **동시성 잠금:** `sink_set_freq()`를 `sink_lock()` 및 `sink_unlock()`으로 감싸고 `pcm_mtx` 보호 하에 `pcm_data`를 비워 하드웨어가 안정화된 후에만 새롭게 정렬된 프레임이 공급되도록 보장합니다.
